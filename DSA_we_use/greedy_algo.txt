# HAC v1 - Greedy Algorithm (Code Walkthrough)

## Why do we use the Greedy Algorithm?

The purpose of HAC (Helix Adaptive Chunking) is to create logical document chunks while preserving the original document structure. Each chunk should stay within a maximum token limit without breaking paragraphs.

A Greedy Algorithm is ideal because it always makes the best decision at the current step. Instead of searching for every possible combination of paragraphs, HAC simply keeps adding the next paragraph until the chunk reaches its size limit.

This approach is simple, fast, predictable, and scalable for large enterprise documents.

---

## Step 1: Initialize Variables

```python
chunks = []
current_chunk = []
current_tokens = 0
```

### Why?

* `chunks` stores all completed chunks.
* `current_chunk` stores the chunk currently being built.
* `current_tokens` tracks the total token count of the current chunk.

Initially, no chunk exists, so all variables start empty.

---

## Step 2: Iterate Through Sections

```python
for section in sections:
```

### Why?

A document may contain multiple logical sections.

Instead of processing the entire document as one block, HAC processes one section at a time. This preserves the document's natural structure.

---

## Step 3: Extract Paragraphs

```python
paragraphs = self._split_into_paragraphs(section)
```

### Why?

Each section is divided into paragraphs because paragraphs represent complete ideas. HAC never breaks a paragraph into smaller pieces.

---

## Step 4: Process One Paragraph at a Time

```python
for paragraph in paragraphs:
```

### Why?

The Greedy Algorithm makes one decision for each paragraph.

Every paragraph is visited exactly once.

---

## Step 5: Count Tokens

```python
paragraph_tokens = self._count_tokens(paragraph)
```

### Why?

Before adding a paragraph, HAC must know how much space it will consume inside the chunk.

The token count determines whether the paragraph fits.

---

## Step 6: Greedy Decision

```python
if current_tokens + paragraph_tokens <= chunk_size:
```

### Why?

This is the heart of the Greedy Algorithm.

The algorithm asks only one question:

> "Can this paragraph fit into the current chunk?"

If the answer is **Yes**, immediately add it.

No future calculations or backtracking are required.

---

## Step 7: Add Paragraph

```python
current_chunk.append(paragraph)
current_tokens += paragraph_tokens
```

### Why?

Since the paragraph fits, it becomes part of the current chunk.

The token counter is also updated.

---

## Step 8: Chunk is Full

```python
else:
```

### Why?

If adding the paragraph exceeds the maximum chunk size, the current chunk must be finalized.

The paragraph is **not discarded**.

Instead, it becomes the first paragraph of the next chunk.

---

## Step 9: Save Current Chunk

```python
chunks.append("\n\n".join(current_chunk))
```

### Why?

The current chunk is complete.

It is converted into a single string and stored permanently.

---

## Step 10: Start a New Chunk

```python
current_chunk = [paragraph]
current_tokens = paragraph_tokens
```

### Why?

The paragraph that did not fit is used to begin a brand-new chunk.

This ensures that no information is lost.

---

## Step 11: Save the Final Chunk

```python
if current_chunk:
    chunks.append("\n\n".join(current_chunk))
```

### Why?

The loop finishes after the last paragraph.

Since no new paragraph arrives to trigger the `else` block, the final chunk must be saved manually.

Without this step, the last chunk would never be stored.

---

## Step 12: Return All Chunks

```python
return chunks
```

### Why?

The function returns every completed chunk generated by HAC.

These chunks become the input for the next stage:

* Sliding Window Overlap
* Chunk Metadata
* ChunkSchema Objects
* Database Storage
* Embedding Generation
* HARE (Helix Adaptive Retrieval Engine)

---

# Time Complexity

Each paragraph is processed exactly once.

**Time Complexity:** `O(n)`

where **n** is the number of paragraphs.

---

# Space Complexity

Additional memory is required only for storing the generated chunks.

**Space Complexity:** `O(n)`

# Interview Explanation (30 Seconds)

> "I implemented the chunk builder using a Greedy Algorithm because the objective is to build the largest possible logical chunk without exceeding the token limit. For every paragraph, I calculate its token count and immediately decide whether it fits into the current chunk. If it fits, I append it; otherwise, I finalize the current chunk and start a new one with that paragraph. Each paragraph is processed exactly once, giving the algorithm O(n) time complexity while preserving paragraph boundaries and document structure. This chunk builder is the foundation of HAC before applying Sliding Window Overlap and HARE retrieval."
